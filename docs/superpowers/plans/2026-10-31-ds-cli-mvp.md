# ds-cli MVP (detect + audit) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npx ds-cli detect`와 `npx ds-cli audit`이 React 레포를 읽어 스타일링 방식·DS 유무·시작 상태를 감지하고, 하드코딩 색·간격 분포와 토큰 후보, 컴포넌트 사용량을 담은 마크다운 리포트를 낸다.

**Architecture:** Extractor 플러그인(`extractor-api` 계약, inline style·Tailwind 구현)이 파일을 `StyleUsage[]`로 바꾸고, `core`가 정규화·인덱싱·클러스터링·매칭을 스타일링 방식과 무관하게 수행한다. `detect`가 어떤 Extractor를 켤지 정하고, `cli`가 이를 묶어 `.ds-cli/*.json`과 리포트를 쓴다.

**Tech Stack:** TypeScript 5.7 (NodeNext ESM), pnpm workspace, vitest, `@babel/parser` + `@babel/traverse` (TSX 파싱), `culori` (색 → oklch), `commander` (CLI), `fast-glob` (파일 탐색).

**Spec:** `docs/superpowers/specs/2026-10-31-ds-cli-design.md`

## Global Constraints

- 패키지 스코프 `@ds-cli/*`, CLI 패키지명 `ds-cli` (이름은 임시, 첫 릴리스 전 일괄 변경)
- Node `>=20`, ESM only (`"type": "module"`), `tsconfig.base.json` 상속, `strict` + `noUncheckedIndexedAccess`
- 커밋 메시지: 한국어 conventional prefix(`feat:`/`test:`/`chore:`/`docs:`), Co-Authored-By 줄 없음, author `dahee <dahee@project-hh.com>`
- Core는 스타일링 방식을 알지 못한다: `packages/core`는 `extractor-*`를 import하지 않는다
- 정규화 단위: 색은 oklch(`{l, c, h}` + 원본 hex), 길이는 px(`rem`/`em`은 16px 기준)
- 대상 레포에 쓰는 파일은 `.ds-cli/` 아래만 (`detect.json`, `index.json`, `reports/audit-<YYYY-MM-DD>.md`)
- 분석 대상 파일: `**/*.{tsx,jsx,ts,js}` 중 `node_modules`, `dist`, `.next`, `build`, `coverage`, `.ds-cli` 제외

## Review Focus

1. 혼용 레포(Tailwind + inline style 동시 사용) — 두 Extractor가 모두 켜지고 같은 파일에서 양쪽 usage가 모두 잡혀야 한다 → Task 9 `mixed-app` fixture 테스트
2. 파싱 실패 파일(문법 오류, 지원 안 되는 구문) — 한 파일이 깨져도 전체 audit은 계속되고 리포트에 "건너뜀 N개"가 표기되어야 한다 → Task 5 `indexRepo` 테스트
3. 동적 값(`style={{ color: theme.primary }}`, `className={cn(base, props.className)}`) — StyleUsage로 잡지 않되 조용히 무시하지 않고 `dynamic` 카운트로 집계 → Task 3, Task 4 테스트
4. Tailwind 기본 팔레트 vs 임의 값 — `text-blue-500`은 `source: "tailwind-default"`, `text-[#3B82F6]`는 `source: "hardcoded"`로 구분되어야 한다. 둘을 섞으면 건강 점수가 왜곡된다 → Task 4 테스트
5. 빈 레포 / 분석 대상 0건 — detect는 `state: 0`, audit는 "분석할 파일 없음" 리포트를 쓰고 exit 0 → Task 8 테스트

- Test: `packages/extractor-api/test/conformance.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type StyleProperty = "color" | "background-color" | "border-color" | "fill" | "stroke"
    | "padding" | "margin" | "gap" | "width" | "height" | "font-size" | "border-radius" | "other";
  export type StyleSource = "hardcoded" | "tailwind-default" | "token" | "dynamic";
  export interface StyleUsage {
    file: string; line: number; column: number;
    property: StyleProperty; raw: string;
    normalized: { kind: "color"; hex: string; l: number; c: number; h: number }
              | { kind: "length"; px: number }
              | { kind: "unknown" };
    source: StyleSource; extractor: string;
  }
  export interface ExtractContext { root: string; file: string; code: string }
  export interface WritePatch { file: string; start: number; end: number; replacement: string }
  export interface Extractor {
    name: string;                                  // "inline-style" | "tailwind" ...
    appliesTo(ctx: ExtractContext): boolean;       // 파일 확장자·내용 기반 빠른 필터
    extract(ctx: ExtractContext): StyleUsage[];
    write(usage: StyleUsage, tokenRef: string): WritePatch | null;
  }
  export function runConformance(name: string, make: () => Extractor, cases: ConformanceCase[]): void;
  export interface ConformanceCase { code: string; file: string; expect: Partial<StyleUsage>[] }
  ```
  `StyleUsage` 등 모델 타입은 이 패키지가 소유하고 `core`가 re-export한다 (core → extractor-api 의존, 역방향 없음).
