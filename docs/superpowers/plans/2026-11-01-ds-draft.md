# Plan 3b: DS 초안 (init · ai · 카탈로그) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 상태 0 레포에서 `dsmith init` 한 번으로 audit 결과를 W3C 토큰 파일(`tokens.json`)·CSS 변수·TS 상수와 컴포넌트 골격으로 내려쓰고 커버리지(= migrate 예상치)를 보고한다. `dsmith ai`는 이 레포의 DS(로컬 디렉터리 / npm 패키지 `.d.ts` / init 산출)에서 컴포넌트 카탈로그 `.dsmith/catalog.json`을 만들고 `AGENTS.md`의 DS 섹션을 갱신한다. MCP 서버는 카탈로그가 있으면 그것을 먼저 읽는다(`source: "catalog"`). 3a가 남긴 훅(토큰 클러스터 결정, 매처 기반 토큰 일치율, 선언 단위 스타일 범위, `.json` 토큰 로더, 제안 이름 중복 규칙 공유, 슬래시 명령 stub 교체)을 모두 닫는다.

**Architecture:** 판단 로직은 core에 둔다 — `cluster/{font-size,names}`, `tokens/{draft,w3c,emit}`(초안 모델·W3C 직렬화/파싱·CSS/TS 방출), `decisions/`(token-cluster 카드·선택·시드·stale, 매처 기반 일치율, 선언 단위 범위), `component/{props,declarations,definition}` 확장(JSDoc·래퍼 유니온·`keyof typeof`·d.ts·이름으로 타입 읽기·파일→module), `catalog/`(모델·저장만), `fs/safe-write`의 `create-only` 모드. 빌더는 새 패키지 둘: `packages/init`(`@dsmith-dev/init`, `runInit`)과 `packages/catalog`(`@dsmith-dev/catalog`, `buildCatalog`·`runAi`). CLI는 `init`·`ai` 서브커맨드로 노출만 한다. mcp-server는 카탈로그 패키지를 import하지 않고 core `readCatalog`로 `.dsmith/catalog.json`을 읽는다.

**Tech Stack:** 기존(TS 5.7 NodeNext, pnpm, vitest, @babel/parser 7.29, culori, fast-glob, picomatch, commander, MCP SDK v2.4) — **새 외부 의존성 없음**. 근거는 부록 B.

**Spec:** `docs/superpowers/specs/2026-11-01-ai-surface-and-init-design.md` (main 8825510) — §2 전체, §3 공통 결정(특히 `ai`의 AGENTS.md 마커 `<!-- dsmith:ds:start -->`/`<!-- dsmith:ds:end -->`, 매니페스트 `.dsmith/ai.json`·`.dsmith/init.json`, 릴리스 버전 메모). 3a 계획: `docs/superpowers/plans/2026-11-01-ai-surface.md`(형식·Global Constraints 계승).

  // cluster/font-size.ts
  export interface FontSizeCluster {
    px: number;                                  // 대표값(정수 px) = 가장 많이 쓰인 값
    members: { px: number; count: number }[];    // count desc → px asc
    total: number;
  }
  export function clusterFontSizes(usages: StyleUsage[], opts?: { tolerancePx?: number }): FontSizeCluster[];
  // 입력: source "hardcoded" && property "font-size" && normalized.kind "length" && px > 0.
  // px = Math.round(px). 서로 다른 값을 count desc → px asc로 돌며, |대표 − px| ≤ tolerancePx(기본 1)인 첫 클러스터에 넣고 없으면 새 클러스터.
  // 결과: total desc → px asc

  // cluster/names.ts
  /** 첫 등장은 그대로, 같은 이름이 다시 나오면 -2, -3 …(이미 쓰인 이름은 건너뜀). 입력 순서 유지 */
  export function uniqueNames(names: string[]): string[];
  /** = uniqueNames(clusters.map(c => c.suggestedName)). proposalTokens·audit 리포트·draft가 같은 이름을 쓴다 */
  export function colorTokenNames(clusters: ColorCluster[]): string[];

  // util/local-date.ts
  export function localDate(d: Date): string;   // cli report/audit-report.ts의 구현을 그대로 옮김

  // tokens/draft.ts
  export type DraftCategory = Token["category"];             // "color" | "spacing" | "radius" | "font-size"
  export type DraftGroup = "color" | "space" | "radius" | "text";
  export interface DraftToken {
    category: DraftCategory;
    group: DraftGroup;              // W3C 그룹 이름 = CSS 변수 접두사
    key: string;                    // 그룹 안 이름: "gray-50" | "2" | "sm" | "full" | "xs"
    name: string;                   // `${group}-${key}` — CSS 변수는 `--${name}`
    value: string;                  // 색 "#rrggbb"(소문자 6자리), 길이 "8px"
    normalized: StyleUsage["normalized"];
    usageCount: number;             // 병합된 원값들의 사용 수 합
    members: string[];              // 병합된 원값("#3c83f7", "13px"), 사용 수 desc
    chosen?: string;                // token-cluster 결정으로 값을 정했으면 그 hex
  }
  export interface ScaleMapping {
    category: "spacing" | "radius" | "font-size";
    px: number; count: number;
    token: string | null;           // 가장 가까운 토큰 name, 그 카테고리 토큰이 없으면 null
    distancePx: number | null;
  }
  export interface TokenDraft { tokens: DraftToken[]; mappings: ScaleMapping[] }
  export interface DraftOptions {
    /** root 상대 POSIX 디렉터리. 이 아래 파일의 스타일은 입력에서 뺀다(init 산출이 다음 init에 섞이지 않게) */
    excludeDirs?: string[];
    /** token-cluster 결정: 색 key(예 "blue-400") → 고른 hex. 그 클러스터의 member일 때만 반영 */
    colorChoices?: Record<string, string>;
    /** 기본 { spacing: 12, radius: 3, fontSize: 8 } — radius의 full은 상한과 별개 */
    limits?: { spacing?: number; radius?: number; fontSize?: number };
  }
  export function buildTokenDraft(styles: StyleUsage[], opts?: DraftOptions): TokenDraft;

  export const COVERAGE_PROPERTIES: readonly StyleProperty[];
  // ["color","background-color","border-color","fill","stroke","padding","margin","gap","border-radius","font-size"] — width/height는 넣지 않는다
  export interface Coverage {
    replaceable: number;            // 토큰으로 바꿀 수 있는 하드코딩 사용 수
    total: number;                  // 대상 하드코딩 사용 수
    rate: number | null;            // replaceable/total 소수 4자리, total 0이면 null
    byCategory: Record<DraftCategory, { replaceable: number; total: number }>;
  }
  /** 대상 = source "hardcoded" && isRatedUsage && property ∈ COVERAGE_PROPERTIES && excludeDirs 밖.
   *  replaceable = rankTokens(normalized, tokens, { category: tokenCategoryOf(property), limit: 1 })[0]?.confidence가 exact|close */
  export function draftCoverage(styles: StyleUsage[], tokens: Token[], opts?: { excludeDirs?: string[] }): Coverage;
  /** 매칭용 Token[] — name은 `--${name}`(CSS 변수와 같은 이름), category·value·normalized 그대로 */
  export function draftToTokens(draft: TokenDraft): Token[];

### B.1 W3C Design Tokens Format Module 2025.10 — 확인

- 출처: https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/ (→ https://w3c.github.io/cg-reports/design-tokens/CG-FINAL-format-20251028/ 로 302). 편집자 초안: https://www.designtokens.org/TR/drafts/format
- 상태: 머리말은 "Final Community Group Report, 28 October 2025", Status 절은 "published by the DTCG as a Candidate Recommendation … considered stable" — 문서 안에서 표현이 엇갈리지만 **안정판**으로 본다. W3C 표준(Recommendation)은 아님
- 토큰 = `$value`가 있는 객체, 그룹 = `$value` 없는 객체. `$type`은 토큰 또는 상위 그룹에(상속). `$description`(문자열), `$deprecated`(boolean 또는 설명 문자열), `$extensions`(벤더 키 — **역도메인 표기 권장**). 그룹은 `$root` 토큰을 가질 수 있음
- 이름: `$`로 시작 금지, `{`·`}`·`.` 포함 금지, 대소문자 구분
- 별칭: `"{group.token}"`(대상의 `$value`로 해석), JSON Pointer `$ref`(`"#/colors/blue/$value"`)
- 타입: color, dimension, fontFamily, fontWeight, duration, cubicBezier, number + 복합 strokeStyle, border, transition, shadow, gradient, typography. **`fontSize`·`borderRadius` 타입은 없다** — 글꼴 크기·모서리는 `dimension`(fontSize는 typography 복합 안의 속성 이름일 뿐)
- **dimension `$value` = 객체 `{ "value": number, "unit": "px" | "rem" }`**, value가 0이어도 unit 필수. 예: `"$value": { "value": 0.5, "unit": "rem" }`
- 파일: 권장 확장자 `.tokens`·`.tokens.json`, 미디어 타입 `application/design-tokens+json`(도구는 `application/json`도 지원해야 함)
- **결정:** (1) 2025.10 객체 형식으로 **쓴다** — 스펙 §2.1 예시(`"$value": "#ffffff"`, `$extensions.dsmith`)는 2025.10 이전 초안 모양이라 갱신한다. 문자열 dimension은 안정판에서 유효하지 않으므로 쓰지 않는다. (2) **읽기는 구형 문자열도 받는다**(Tokens Studio·Style Dictionary 구형 파일 호환). (3) 확장 키는 `"dev.dsmith"`. (4) 파일 이름은 스펙·detect 글롭(`tokens.json`)을 따라 `tokens.json` 유지 — 권장 확장자 `.tokens.json`과 다르지만 `.json`이라 도구 호환에 문제없고, detect가 이미 이 이름을 토큰 파일로 잡는다

### B.2 W3C Design Tokens Color Module 2025.10 — 확인

- 출처: https://w3c.github.io/cg-reports/design-tokens/CG-FINAL-color-20251028/ (Final CG Report, 2025-10-28, "considered stable")
- color `$value` = 객체 `{ colorSpace (필수, 예 "srgb"), components (필수, 숫자 또는 "none" 배열), alpha (선택 0~1, 생략 시 1), hex (선택 폴백) }`. srgb 각 성분 0~1. `hex`는 **6자리 CSS hex**(3·8자리 불가), 예시는 모두 소문자 `#`. **평문 hex 문자열은 `$value`로 허용되지 않음**(문자열은 별칭뿐). 예: `{ "colorSpace": "srgb", "components": [1, 0, 1], "alpha": 1, "hex": "#ff00ff" }`
- 결정: `{ colorSpace: "srgb", components: [r,g,b] (소수 4자리), hex }`, alpha는 1이라 생략(정규화된 hex가 이미 alpha를 버림)

### B.3 Babel parser — 확인(문서 + 로컬 프로브, 레포의 @babel/parser 7.29.12)
